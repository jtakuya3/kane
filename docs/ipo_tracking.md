# IPO情報収集・一覧表管理 指示書

## 概要

2026年以降の日本株IPO（新規上場）の情報を継続的に収集し、投資判断に必要な一覧表を維持・更新するための詳細指示。
ユーザーが「IPOチェック」「IPO更新」等と発話した際、または Claude Code on the web の Routine による毎日20:00 JST の自動起動時に、本指示に基づいて情報収集→差分報告→一覧表更新を実行する。

### 管理シート

- **Notion（マスター）**: https://www.notion.so/ba01199582c243d3be0e1db8d1c50c69
  - ページ名: 📈 IPO情報まとめ
  - データベース: 📋 IPO候補（インライン埋め込み）
- すべての更新はこの Notion データベースに対して Notion MCP を使って行う。ローカルファイルや Google Sheets は使用しない。

## 1. 情報収集のトリガーと頻度

### 定期チェック（Routine による自動起動）
- **Claude Code on the web の Routine で毎日20:00 JST に自動起動**
- 起動時に「新規承認」「ステータス変更」「初値確定」を確認し、Notion データベースを更新

### 積み上げ式チェック（毎回すべては調査しない）
- 前回チェック以降に**ステータスが変化した銘柄**のみを対象に深掘り調査を行う
- すでに「上場済」または「見送り」のステータスになった銘柄は再調査しない
- 新規承認銘柄は基本情報（§3 基本情報）のみ取得し、詳細は仮条件決定後に埋める
- Notion の「更新」列（last_edited_time）を参照し、直近24時間以内に更新されていない銘柄を優先チェック対象とする

### 手動チェック（ユーザー発話時）
- 「IPOチェック」「IPO更新」「新規承認あった？」等の発話で起動

### 即時チェックが必要なイベント
- 新規上場承認（東証発表、通常は上場1ヶ月前）
- 仮条件決定（BB開始前後）
- 公開価格決定（BB終了翌営業日）
- 初値確定（上場日当日）
- 仮条件の上ブレ/下ブレ（想定価格との乖離）

## 4. 同業PER比較の調査方法

### 手順
1. **目論見書の「事業の内容」セクション**から比較対象企業を特定
2. 目論見書に記載がない場合、以下の基準で自分で選定：
   - 同一業種分類（東証33業種）
   - 類似ビジネスモデル（PF型/仲介型/受託型/SaaS型等）
   - 類似時価総額帯（±3倍以内）
3. **各比較企業の現在PER**をYahoo!ファイナンスまたはみんかぶから取得
4. ディスカウント幅を算出（IPO銘柄のPER ÷ 同業PER）

### 注意事項
- IFRS採用企業はのれん非償却でPERが低く見えるため、J-GAAP換算PERも併記
- 赤字企業はPSR（株価売上高倍率）で比較
- 黒字転換期の企業は実績PERが異常値になるため予想PERを使用
- M&A仲介/PF系は同業でもPER帯が10倍〜50倍と幅広い。ビジネスモデルの違い（仲介 vs PF vs SaaS）を明記

## 5. ステータス管理

各銘柄に以下のステータスを付与し、進行状況を把握する。

| ステータス | 意味 | 次のアクション |
|-----------|------|--------------|
| ウォッチ | 上場承認発表済、想定価格あり | 仮条件待ち |
| 調査中 | 詳細調査中 | 各種情報入力 |
| ブックビル | ブックビルディング期間中 | 参加/見送り判断 |
| 上場予定 | 公開価格確定、当選結果待ち | 上場日待ち |
| 上場済 | 初値確定 | セカンダリー判断 or 完了 |
| 見送り | BB見送り決定 | 再調査不要 |

## 6. 差分報告のフォーマット

チェック実行時、以下の形式で報告する。

```
【前回チェック日: yyyy/mm/dd → 今回: yyyy/mm/dd】

■ 新規承認（前回以降）
- [銘柄名]（コード）上場日: mm/dd, 主幹事: ○○, 想定価格: ○○円

■ ステータス変更
- [銘柄名]: 仮条件決定 → ○○〜○○円（想定比: 上ブレ/同値/下ブレ○%）
- [銘柄名]: 公開価格決定 → ○○円（仮条件上限/下限）
- [銘柄名]: 初値確定 → ○○円（騰落率: +○%/-○%）

■ 5月上場分の新規承認: あり/なし

■ Notion 更新: 必要/不要（更新件数: N件）
```

## 9. 注意事項・フラグルール

### メモカラムに自動フラグを立てるべき条件
- **🚩 IFRS採用**: のれん非償却。PER割安に見えるが実質は高い可能性
- **🚩 公募0%/売出100%**: 完全イグジット型。創業者・VCの出口
- **🚩 仮条件10%超下ブレ**: 需要不足のシグナル
- **🚩 吸収50億超（グロース）**: 需給重い
- **🚩 VC保有20%超**: ロックアップ解除後の売り圧力
- **🚩 親子上場**: ガバナンス懸念
- **✅ 吸収5億以下**: 需給好条件
- **✅ 単価1,000円以下**: 買いやすさプレミアム
- **✅ 配当3%超**: バリュー投資家の参入余地
- **✅ 全株ロックアップ（価格解除なし）**: 上場直後の売り圧力限定

## 10. Notion 更新手順（積み上げ式）

### 基本方針
- **積み上げ式**: 毎回すべての銘柄を再調査するのではなく、前回チェック以降に変化があった銘柄のみを対象に更新する
- Notion MCP (`notion-search`, `notion-create-pages`, `notion-update-page`) を使って直接データベースを操作する
- 新規銘柄は `notion-create-pages` で追加、既存銘柄の更新は `notion-update-page` で行う

### 更新対象 Notion ページ
- **Notion URL**: https://www.notion.so/ba01199582c243d3be0e1db8d1c50c69
- **データベース collection ID**: `bc64f8a0-423a-44c1-bb3f-a95a2d66e961`

### 更新手順
1. Notion の「IPO候補」データベースを `notion-search` または `notion-fetch` で取得し、現在の銘柄一覧とステータスを確認する
2. 新規承認銘柄は `notion-create-pages` で最下行に追加（基本情報のみ入力、未確定は空欄）
3. ステータス変更のある銘柄は `notion-update-page` で該当カラムを直接更新
4. 初値確定した銘柄はステータスを「上場済」に変更し、初値・騰落率を入力
5. 更新内容のサマリーを差分報告フォーマット（§6）でユーザーに通知

### 積み上げ更新ロジック
```
1. notion-fetch で現在の DB 内容を取得
2. ステータスが「上場済」「見送り」の銘柄 → スキップ（再調査不要）
3. ステータスが「ウォッチ」「調査中」「ブックビル」「上場予定」の銘柄 → 更新対象
4. 新規承認のチェック（JPX/庶民のIPO） → 未登録銘柄があれば追加
5. 各更新対象銘柄のステータスに応じて必要なカラムのみ調査・更新
```
